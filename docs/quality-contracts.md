# HTTP contracts (HP-72)

`src/api/__fixtures__/api-contract.generated.json` is generated by the backend
`ConsumerContractTests` through real HTTP serialization and isolated PostgreSQL.
Do not hand-edit it. Backend documentation describes intentional regeneration.
The old PascalCase attendance fixture protects legacy compatibility only.

`backendContract.test.ts` runs these responses through production API parsers.
`scripts/quality/compare_contract.py` rejects drift from the backend fixture,
including nested casing changes. CI checks the same-named backend task branch
when it exists, otherwise backend develop. Both branches must be pushed before
coordinated PR validation; no token or private data is needed for these public repos.

A coordinated contract change needs two reviewed PRs. During initial rollout,
or between the two merges, staging validation can fail closed until both sides
are present. Rerun that validation after the companion merge. Never disable the
check, normalize mismatched DTO keys, or refresh fixtures automatically in CI.
